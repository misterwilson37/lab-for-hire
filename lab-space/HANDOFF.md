## 3. Merging into `index.html` (main-game session 4)
1. **Paste the module.** Copy the whole `<script id="lab">…</script>` block from `src/lab_template.html` into `index.html`. It injects its own CSS and inherits the page font.
2. **Add three generated JSON blocks** the same way `lfh-content` is generated: `lab-items`, `lab-manifest`, and `lab-sprites` (a map of file name → data URI). `src/build_lab.py` shows how. Extend `tools/embed_content.py` to do it.
3. **Add the lab to saved progress** as `progress.lab`. `LabRoom.normalize(progress.lab, items)` always returns a valid v2 lab, and it upgrades v0.1.0 saves.
4. **Mount it:**
   ```js
   const lab = LabRoom.mount(el, {
     state: progress.lab, items, rank: rankIndex, rankName: (n) => RANKS[n].name,
     onChange: (next, ev) => { progress.lab = next; saveProgress(); }   // ev.type: buy | place | remove | paint | award
   });
   ```
5. **Pay funds from the game, never from the module.** At the end of a case: `const s = lab.getState(); s.funds += earned; lab.update(s); lab.say("+$40 for solid evidence")`.
6. **Award the framed graph.** When a student earns it (Hanson decides what counts: first try with no misses, or simply finishing a case), the game calls one of these:
   - `lab.grant("graph-frame", { title, type, points })` when the lab is mounted.
   - `progress.lab = LabRoom.grant(progress.lab, items, "graph-frame", data)` when it isn't.

   `type` is `"line"`, `"bar"`, or `"scatter"`. `points` is `[[x, y], …]` straight from the graph the student built (Build mode already has these). No text is drawn on the poster; `title` shows only in the module's messages.
7. **Gate cases by what the student owns.** `LabRoom.unlocks(progress.lab, items)` returns keys like `["cells"]`. It counts owned equipment, whether it's out or in storage.
8. **Rank changes:** call `lab.setRank(n)`.
9. **Remove the old placeholder.** Delete the emoji lab shelf and the demo glue (`<script id="lab-demo">`).

**Lab state v2** (item IDs only, no PII):
```js
{ v: 2, funds: 70, owned: ["desk", "microscope", "work-table", …],
  rooms: { main: { placed: { bench: "desk", "table-1": "microscope", … },          // spot id → item id; owned but absent = in storage
                   paint:  { wall: "wall-any", floor: "floor-lilac", trim: "trim-purple", tiles: "tiles-plain" },
                   colors: { wall: "#1F8FBF" } } },                                   // only for Any Color paints
  awards: { "graph-frame": { title: "Movin' Molecules", type: "line", points: [[0, 21], [2, 30], …] } } }
```
- **One of each item.** An item is out in at most one room; everything owned that isn't out is in storage.
- **Room names:** today only `main` exists. A wing would add, say, `rooms.greenhouse` with its own manifest (its own spots and bake), and `mount(el, { manifest: greenhouseManifest, … })` would show it. The module already reads the room id from the manifest (`roomId`, default `main`), and `normalize` already keeps items that are out in other rooms out of this one.

**Content schema:** the Items tab bumps the content schema to **0.3.0**. Port `tools/lab-bake/bake.py → validate()` into `LFH.validate`. It checks:
- IDs are unique, and Kind is Equipment, Cosmetic, Theme, or Award.
- Awards have Price 0.
- Slot names a real spot type.
- Sprite names a baked look, a `#hex`, `any`, or a pattern.
- There is exactly one free starter row for each paint kind.

## 4. Decisions made (and why)
- **The save code is dropped.** If a device dies, the code dies with it. Saving will move to accounts with the same COPPA setup as Jake's other sites. That is decided, and it will be built in another conversation. It replaces "save code" in main-game session 2 and changes the brief's "no accounts" rule.
- **The framed graph is an award, not a purchase.** The student already made the graph; paying for it would be odd.
- **More room comes from wings tied to units, not a copy of the lab.** For example, a Greenhouse wing opens with the plant unit, and the Grow Cabinet lives there. Wing ideas go to Hanson first.
- **Extra spots need furniture under them.** The Work Table must be bought before its two spots appear.
- **The Work Table runs along the right edge**, long side front to back. Placed out in the middle, it covered the chair and the rug.
- **Any Color sits on top of the presets.** The 16 presets steer kids toward colors that look good in the room, and the full picker is still there.
- **Items from v0.1.0 that still stand:**
  - 14 spots became 17 with the table.
  - The demo has its own storage key, `lfh.labDemo`.
  - Furniture sits against the baseboard.
  - Bookcases are sized by their top board.
  - The Kenney skeleton was dropped for the Spark Coil.

## 5. Art pipeline (Rules 9 and 10)
- **Locked setup:** one orthographic camera and one light rig, defined in `scene.js`. Each item is baked alone in its spot and cropped with its offset kept, so the iPad just layers images.
- **Shadows:** invisible shadow-only planes catch each item's shadow on the floor, walls, and baseboard, or on the bench, Work Table, or shelf top.
- **The room shell is code-shaded polygons**, which is why Any Color costs nothing to support.
- **The graph award:** the bake records where each poster spot's canvas lands on screen (`slots[].canvas`). The module draws the student's graph there with the same wall shading.

**Rule 10 result** (`overlay-check/overlay_sheet.png`). The upgraded lab includes the Work Table with two items. The designer lab has Any Color walls and the empty award frame.

| Lab | Within 8 shades | Wrong pixels beyond 1-px outlines (of 1.92 M) |
|---|---|---|
| Starter | 99.46% | 0 |
| Frankenstein (with two portraits) | 99.33% | 12 |
| Designer paint | 99.06% | 185 |
| Upgraded | 99.14% | 1,160 |

- **Known limitation:** one item's shadow falling onto another item is not captured. The biggest case is the Grow Cabinet shading the side of the bench.
- **Not in this check:** the drawn graph itself. It was checked by eye; it sits inside the canvas on both walls.
